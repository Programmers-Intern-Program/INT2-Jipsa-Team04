2. 외부 전용 구조

RAG/.env.local
  ├─ JIPSA_RAG_EXTERNAL_BASE_URL
  ├─ RAG_INGEST_TOKEN
  ├─ JIPSA_RAG_QDRANT_*
  └─ JIPSA_RAG_DATABASE_*
          │
          ▼
RAG-Performance Control Plane
  ├─ Qdrant → DB → Snapshot 자동 Fallback
  ├─ 실제 Users_IDX / File_IDX 무작위 선정
  └─ 외부 Search 결과 사전 검증
          │
          ▼
외부 Jipsa RAG /api/v1/chunks/search
중요: 데이터 선정에서 Local Qdrant·DB를 읽을 수 있지만 실제 부하는 항상 JIPSA_RAG_EXTERNAL_BASE_URL로만 전송됩니다. 운영 Collection과 DB는 수정하지 않습니다.

5. 기존 데이터 자동 선정

1. Qdrant
우선
2. DB
Fallback
3. Snapshot
최종

Qdrant

is_active=true Point의 users_idx, file_idx, content만 읽고 Vector는 읽지 않습니다.

Local RAG DB

Qdrant 접근 실패 시 RAG_Document.Index_Status='INDEXED', Deleted_At IS NULL 조건으로 SELECT만 수행합니다.

Snapshot

snapshots/, 저장소 Root와 RAG/에서 최신 *.snapshot을 찾습니다. 운영 Qdrant가 아닌 임시 Container·임시 Collection에 복원한 뒤 반드시 제거합니다.

무작위 선정

  • 파일 수 조건을 만족하는 User 중 무작위 선택
  • 활성 File IDX 무작위 선택
  • 실제 Chunk Content로 Query 생성
  • Seed 기록
  • 외부 Search의 result_count > 0 검증

8. 파괴적 외부 테스트

11. Quick Start

& .\scripts
un-staged-stress-test.ps1 `
    -TestProfile quick `
    -SkipQualityGate

외부 주소가 HTTP이면 Test 환경에서 AllowInsecureHttp를 자동 적용합니다.

12. Capacity Ladder·Standard·Endurance

Quick C32가 상한 검열 상태이면 같은 Seed와 같은 데이터로 Standard C128까지 자동 승격합니다. Destructive C256은 명시적으로 승인한 경우에만 이어집니다.

& .\scripts\run-capacity-ladder.ps1 `
    -SkipQualityGate

& .\scripts\run-capacity-ladder.ps1 `
    -AllowDestructive `
    -ConfirmTargetHost 'int2-jipsa.iptime.org' `
    -SkipQualityGate

단일 Profile 실행:

& .\scripts\run-staged-stress-test.ps1 -TestProfile standard -SkipQualityGate
& .\scripts\run-staged-stress-test.ps1 -TestProfile endurance -SkipQualityGate

22. 설계 원칙

  1. 부하 생성기와 RAG를 분리합니다.
  2. 사용자 Secret·식별자 반복 입력을 제거합니다.
  3. 운영 데이터는 읽기 전용으로 탐색합니다.
  4. Snapshot은 격리된 Qdrant에서만 해석합니다.
  5. Seed를 기록해 재현성을 보장합니다.
  6. 검색 결과가 있는 데이터만 부하에 사용합니다.
